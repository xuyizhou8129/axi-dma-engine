The call_back test is a manual put in arbitrary data and read out data what are supposed to be moved to,
It has been passed on our Vitis environment
The uart_read_write is supposed to be a further test using uart from host as stimulations instead of arbitrary poke,
the local computer runs a python script host_runner.py to send uart signals over to Microblaze, which then preload the values in sys_mem
and sram based on the uart message


serial_host.py will call the run_golden.py, and then specify a csv file in scenario, will be a global parameter that
can be specified in command line instruction
(You may also have to modify run_golden.py so the sim.txt it outputs is exactly the same format as the firmware/stim.txt)
Also, in serial_host.py, the final CRC value shouldnt be hardcoded but calculated based on the hex files generated by the software model

Afterwards, the workflow should be:
I run serial_host.py,
it runs software model on a csv scenario
it gets two correct CRC values, one for sys_mem, one for sram
it also sends the stim.txt obtained after running sw model to my FPGA through uart
When modifying serial_host.py you can reference host_runner.py to learn about how to interact with my firmware (what format of uart message is needed)
